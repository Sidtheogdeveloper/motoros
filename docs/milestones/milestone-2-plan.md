# Milestone 2 implementation plan

1. Record the existing Java, Node, HTTP and browser baseline; retain the reviewed Milestone 1 source archive as a recoverable checkpoint. Read the existing architecture, contracts and local-auth decision. No application data is deleted.
2. Replace the development password signer with standards-based OIDC: Keycloak locally and configurable Cognito issuer/JWKS/client endpoints. Use Authorization Code + PKCE, state and nonce. Keep opaque, expiring application sessions in Redis with encrypted token payloads and server-side refresh/revocation. Mailpit receives development email only.
3. Extend the Tenant schema through Flyway: external issuer/subject identities, multi-brand memberships, scoped branch assignments, permission catalog, invitations, durable mail delivery and administrative audits. Remove legacy password hashes; legacy identities require an explicit development migration or operator mapping, never automatic ownership based only on email.
4. Make Tenant authoritative for live authorization. Resource services validate provider JWTs independently, then obtain current membership context using authenticated service clients. Delegated internal calls validate both the service identity and original user token. Fail closed if the authority is unavailable; do not cache membership permissions.
5. Implement transactional onboarding, complete brand/branch administration, role-aware staff management, single-use verified-email-bound invitations and final-owner/escalation controls. Preserve Customer and Work Order APIs behind the new context boundary.
6. Integrate actual frontend flows for hosted identity, onboarding, profile, brand switching, branches, staff, invitations and role-aware workspace navigation. Partition/clear queries by identity and selected brand; branch selection adds no authority.
7. Verify with JUnit/Testcontainers, live OIDC/SMTP/Redis/API integration and Playwright. Document passed and unverified acceptance criteria separately. Provide Cognito Terraform/configuration templates without applying them. Do not start Milestone 3.

Milestone 1 baseline is recorded under task-local work/m2-baseline-* logs and will be summarized in the milestone report. The prior 21 Java, five Node, 38 HTTP and six browser checks are preserved as baseline evidence; authentication-specific cases will be migrated rather than retaining a bypass for obsolete HS256 tokens.
